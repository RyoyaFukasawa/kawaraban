## プロジェクト改善考察

**fetch の仕組みは妥当か**
鮮度フィルタ（36h）は正常動作している模様。ただし取得成功率が低く（4/18ソース）、実質的に TechCrunch・CNBC・PBS・NPR に過度に依存している状態。重複排除は 20/20 件が新規追加されており正常。

**本当に最新・先進の情報が取れているか**
AI カテゴリ（先進性優先）は Reddit から Cohere BLS-Mini-Code-1.0・DeepSeek V4 Flash・KVarN KV cache といった新モデル・研究情報を拾えており、機能している。ただし Hugging Face ブログが 403 で取得不能なのは一次情報源として痛い。Hugging Face blog の直接 RSS を見直すか、Papers With Code などの代替追加を検討すべき。

**ソース構成の穴**
- Economy: AP Economics や Reuters のような無料フルテキスト配信のソースが不足。現在は FT（ペイウォール）・NYT（ペイウォール）・BBC（403）・NPR（成功）の4ソースだが実質 NPR のみ機能。
- AI: IEEE Spectrum・The Robot Report は本日候補なし。ロボティクス分野の一次情報が薄い。
- Politics: 米国内に PBS/The Hill が偏っており、国際政治（欧州・アジア）視点が不足。

**選定ロジック・枠**
MAX 5/カテゴリで適切。AI カテゴリ先進性優先の方針は継続観察中（2026-06-02 開始）。今日は 3件が Reddit ⚠️ 印で、未確認情報の割合が高い点は注意が必要。Hugging Face の一次情報が取れれば品質向上が見込める。

**パイプライン全体**
npm run ingest・build-md とも正常完了。Reddit の description から本文を活用する運用は事実上の workaround として定着してきたが、正式に「description フィールド fallback」として fetch スクリプトに組み込むと安定性が増す（週次 IMPROVE_PROMPT.md の PR 候補）。
