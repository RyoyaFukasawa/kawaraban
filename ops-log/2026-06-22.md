- **OpenAI.com 403継続**: 公式ブログは一次情報として最重要だが本文取得不可。RSS description は200字前後と薄い。要約品質に影響（day 4以上継続）。

- **NYT Business 403継続**: economy のUS視点が弱い。PBS Economy + BBC Business + NPR Economy の3ソースだけでは1記事/日しか出ない。
- **Financial Times全ペイウォール**: INSIGHTS.md記載の通り。economy の最大の構造的穴。代替候補なしのまま。
- **Reddit r/LocalLLaMA 403**: コミュニティ速報として有効だが本文取得不可。description のみで⚠️をつけて採用しているが、元スレの裏取りが困難。
- **politics 54候補 / 2採用**: BBC World の速報重複を鑑みると実効採用率は低い。Reutersや解説系ソース（Foreign Affairs等）の追加余地あり。

## プロジェクト改善考察

**fetch の仕組みは妥当か**

RSS取得は19/19成功し36時間鮮度フィルタも正常。ただし「RSS取得OK」と「本文取得OK」は別であり、
現状 OpenAI・The Hill・NYT Business・FT の4ソースは実質的に「RSSヘッダーしか取れない」状態が
常態化している。body fetch 失敗を ops-log に記録する仕組みはあるが、fetch-article コマンドが
403を返すだけで自動リトライや代替取得の仕組みはない。週次ルーティンで body_ok フラグを
articles.json に持たせ、description代替の割合を追跡する仕組みを検討したい。

**本当に最新・先進の情報が取れているか**

本日のAI枠はOpenAIの新Daybreak/Samsungモデル展開、HuggingFace PP-OCRv6、DeepSeek・TMax
（Reddit）と一次情報カバレッジは確保できた。ただし OpenAI 本文が取れないため、
「発表の概要」しか把握できていない。Anthropic の公式ブログ（INSIGHTS.md記載のpending）が
未追加のままで、例えば今日 John Jumper が Anthropic に移籍したニュース（CNBC Technology経由）を
Anthropic 側の一次情報として補完できなかった。

**ソース構成の穴**

- economy: FT + NYT Businessが実質不在で、US経済視点は NPR Economy（1件/日）頼み。
  Bloomberg無料RSS や CNBC Economy の追加が急務。継続問題（INSIGHTS.md既出）。
- politics: The Hill 403 + BBC World 重複過多 = 米政治の独自報道カバレッジ不足。
  Politico RSS か Reuters Politics の追加を検討。
- robotics: 候補が5件と少ない。The Robot Report単独では薄い日が出る。IEEE Spectrum等要検討。

**選定ロジック・枠**

MAX_PER_CATEGORY=5 は適正。本日 politics のみ2件で止まったが、これは品質基準の維持の結果であり
枠を無理に埋めるより望ましい。UNVERIFIED_RATIO_CAP=0.40 は今日ちょうど境界（2/5=40%）。
Reddit の⚠️記事は本文も取れず quality が下がりがちで、cap を下げる（上限1件/5件）案も考えられる。
ただしAI速報として Reddit は有用なため、本文 fetch が回復した場合の品質を見て判断したい。

**パイプライン全体**

fetch-article の403時に description を使う「graceful degradation」は実用的に機能している。
ただし要約品質の不均一（本文あり vs descriptionのみ）が読者体験に影響しうる。
summary の末尾に「（本文取得不可・RSS要約）」のような注記を自動付与するオプションを検討。
build-md と ingest は今日も問題なく完走。
