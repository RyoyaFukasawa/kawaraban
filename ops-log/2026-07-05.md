## プロジェクト改善考察（収集メモではなく「仕組みをどう良くするか」の所感）

### fetch の仕組みは妥当か

36h 鮮度フィルタと重複排除は今日も正常に機能しており、115 件という適切な候補数が得られている。一方で、raw-items.json の `paywalled` フラグが fetch-feeds 段階で正確についていない場合（NYT Business 事例）、ingest/summary ステップで「実は本文取れない」と後から判明するパターンが残存している。fetch-article 実行時に `paywalled` フラグをリアルタイム更新する仕組みがあれば、選定段階でより正確な判断ができる。

### 本当に最新・先進の情報が取れているか

本日の AI 枠は全件 Reddit r/LocalLLaMA（longcat 2.0 MIT公開・Qualcomm GenieX・13モデルベンチマーク・Supra-Router・Qwen 3.6 27B）。どれもコミュニティ発の速報性は高く、内容の先進性は一定水準を保っているが、全件 unverified という状態は改善が必要。Anthropic Blog・OpenAI Blog・Hugging Face から本日何かリリースがあったかは確認できないが、それらが取得できていれば公式発表を一次情報として拾える。

### ソース構成の穴

1. **AI**: Anthropic Blog 未追加（PR improve/feeds-2026-06-28 未マージ）が最大の構造的欠落。週末・土曜に Reddit 100% 占有が定常化しており、6 月 21 日の初出から 2 週間後の本日も解消されていない（🔴悪化）。
2. **Robotics**: The Robot Report 1 件のみという危機的状況が継続。IEEE Spectrum/NVIDIA Robotics の機能不全に加え、TechCrunch Robotics フィード追加期限（2026-07-12）が 1 週間後に迫っている。期限内の対応を強く推奨。
3. **Economy**: 本文取得可能なソースが実質ゼロの状態が常態化。RSS description だけでも選定・要約はできているが、投資判断に必要な数値や詳細が description に含まれない場合は質が低下する。Reuters/AP 追加または FT/NYT 代替の検討を加速すべき。
4. **Politics**: 60 件候補中 5 件採用。候補過多（重複速報）の問題は依然あるが、CBS+PBS で本文 OK の記事は確保できており politics 枠は機能している。BBC/The Hill の 403 は残存課題だが priority は低い。

### 選定ロジック・枠

UNVERIFIED_RATIO_CAP（PR #16）の未マージにより、AI 枠の 100% Reddit 占有が 2 週間以上継続している。マージが実現するまでは日次 routine が手動でキャップを意識する必要があるが、5 件全件が Reddit unverified になる日は公式ソースの代替がなく、運用で回避することは困難。PR マージが根本的解決策。

### パイプライン全体

ingest → build-md のパイプラインは本日も正常完了（21 件追加、37 日分 + カテゴリ 5 件 + README 生成）。article-bodies/ ディレクトリに保存される本文ファイルの番号付けが implicit（取得順）になっているが、現状の運用では問題なし。fetch-article の 403 エラーは明示的なログ出力がないため、次回実行時に本文の有無でしか判別できない点は改善余地がある（SKIP として明示 or description fallback を自動化することで、人手の判断を減らせる）。
