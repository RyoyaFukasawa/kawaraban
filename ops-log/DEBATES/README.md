# DEBATES — 週次の発散→収束ログ（ブレスト＋対立議論）

週次の改善 routine（[../../IMPROVE_PROMPT.md](../../IMPROVE_PROMPT.md)）が、日次の
「プロジェクト改善考察」をもとに **2段階**で改善を練った記録を残す場所。1回の週次実行につき1ファイル。

- **フェーズA: ブレスト（発散）** — 複数の発想レンズのagentが、批判抜き・量重視で改善アイデアを出す。
  新しい論点・着眼点そのものを生むのが目的。
- **フェーズB: 対立議論＋裁定（収束）** — ブレスト案＋日次の既存論点を、推進派⇄懐疑派でぶつけ、
  第3のジャッジが「やる/やらない/保留」を裁定する。

- ファイル名: `YYYY-MM-DD.md`（週次実行日）
- 人間（リポジトリオーナー）はこれを**読んで楽しむ／必要なら口を出す**。書き込みは不要。
- 「やる」と裁定された改善は、同じ週次実行が PR にする（PR 本文にこの議論ログを含める）。

## フォーマット

````markdown
# 週次 発散→収束ログ YYYY-MM-DD

対象期間: YYYY-MM-DD 〜 YYYY-MM-DD
読んだ日次ログ: N 件（YYYY-MM-DD, ..., 全件リスト）  ← 7日分を必ず全件読む
日次から拾った既存論点: K 件

---

## フェーズA: ブレスト（発散・批判禁止・量重視）

3つの発想レンズの agent が、**互いの案に乗っかり合いながら**アイデアを広げる。ここでは良し悪しを
判定しない（批判は禁止。収束はフェーズB）。**必ず直近7日の日次ログ（気づき・プロジェクト改善考察・
fetch結果）を全件読んでから**発想する。

レンズ:
- **🔭 ソースハンター**: 拾えていない一次情報源・カテゴリ・地域・非英語圏など。
- **🙋 ユーザー代弁（投資家読者の視点）**: 読み手にとっての価値・不足。薄い/重複/役に立たない枠の指摘。
- **💡 斬新枠（ワイルドカード）**: 取得頻度を変える/新カテゴリ/全く別の角度/思い切った再設計など。

### 💬 ブレスト議事録（逐語・時系列・触発の連鎖）
各レンズの発言を**実際のまま・発言順に**残す。要約しない。**ラウンド数は固定しない**——アイデアが
湧き続ける限り続け、出尽くしたら止める。肝は「乗っかり」: 誰かの案に別レンズが「**それなら**こういう
案も」と発展させたやり取りを省かず記録する（発散が連鎖する様子こそ価値）。批判はしない（"いいね、
さらに" の方向で広げる）。各発言に「レンズ絵文字・Tn」を付ける。

```
🔭 ソースハンター [T1]: <案＋なぜそう思ったか（どの日次ログの何から）>
🙋 ユーザー代弁  [T2]: <T1に乗っかる、または別角度の案。「それなら読者は〜も欲しいのでは」>
💡 斬新枠        [T3]: <T1/T2を飛躍させる案。「いっそ〜という手もある」>
🔭 ソースハンター [T4]: <T3に触発された新案>
🙋 ユーザー代弁  [T5]: ...
（... アイデアが湧く限り続け、出尽くしたら止める。全発言を残す ...）
```

- 「なぜそう思ったか」の思考過程と、「誰の案に乗ったか」の連鎖を残す（単なる案の羅列にしない）。
- 突飛でも書く（実現性の判定はフェーズBのジャッジに任せる）。

### ブレストまとめ
- 出たアイデア一覧（重複は束ねる）: <番号付きで列挙>
- 今週フェーズBに送る新規アイデア: <一覧>
- 即却下（明らかに非現実的）: <一覧と一言理由>

---

## フェーズB: 対立議論＋裁定（収束）

フェーズAの新規アイデア＋日次から拾った既存論点を合わせ、重要なものを 2〜4 件選んで議論する。

## 論点1: <論点の見出し>

**背景**: なぜこれが論点になったか（どの日次ログ・どの繰り返しパターンから来たか）

### 💬 議論ログ（逐語・時系列の議事録）
推進派🔵と懐疑派🔴の**発言を実際のまま、発言した順に**残す。要約しない。**ラウンド数は固定しない**
（噛み合う/深まる限り何ラリーでも続け、全ラリーを記録する。打ち切るのは、論点が出尽くした・
堂々巡りになった・合意/平行線が明確になった時）。各発言は「誰が・何ターン目か」を頭に付ける。

```
🔵 推進派 [T1]: <最初の主張。具体策＋根拠（どの日次ログの何を見て言うか）>
🔴 懐疑派 [T2]: <それへの反論。リスク・コスト(token含む)・反証・副作用。推進派の具体策の穴を突く>
🔵 推進派 [T3]: <懐疑派のどの指摘に答えるか明示して再反論。必要なら案を修正>
🔴 懐疑派 [T4]: <さらに反論、または部分的に同意して論点を絞る>
🔵 推進派 [T5]: ...
🔴 懐疑派 [T6]: ...
（... 議論が続く限り T7, T8, ... と全発言を残す ...）
```

- 発言は実際の中身を書く（「再反論した」ではなく、何と言って反論したか）。
- 譲歩・前提の修正・「そこは認めるが」といった**論の動き**も省かず残す（議論の価値はそこにある）。
- 途中で事実確認が必要になったら、確かめた結果（HTTPコード等）も発言の中に記録する。

### 🧷 論点の到達点（議論の要約・ジャッジ用の手がかり）
- 合意できた点 / 平行線のままの点 / 未解決で持ち越す点を 箇条書きで短く。

### ⚖️ ジャッジ裁定
- **結論**: やる / やらない / 保留（条件付き）
- **理由**: 上の議論ログの**どのターンのどの発言**が決め手か（ターン番号で参照する）。
  両論のうち何を採り何を退けたか。
- **保留の場合**: 何が分かれば結論が出るか（次に観測/検証すべきこと）
- **PR化**: する/しない。するなら具体的に何を変えるか（ファイル・変更内容）

---

## 論点2: ...
（同じ構造を繰り返す。各論点ごとに逐語の議論ログを残す）

---

## まとめ
- PR化する改善: <一覧>
- 保留（継続観測）: <一覧 → INSIGHTS.md の論点トラッカーへ反映>
- 却下: <一覧と理由>
````

## 運用ルール
- **必ず直近7日の日次ログを全件読んでから**ブレスト・議論する（フェーズAの発想もフェーズBの論点も
  日次ログ＝現場の一次データに根ざす。読んだファイルは冒頭に全件リストアップする）。
- 議論・ブレストは**実際に複数のagentを立てて行う**（ブレストの各レンズ、推進派・懐疑派・ジャッジを
  別agentにし、役割を固定する）。1体に「全部演じて」と頼むと中庸に流れるので、独立agentに割り当てる。
- ブレストは**批判禁止・量重視**（発散）。良し悪しの判定はフェーズBに回す。
- **ブレストも議事録を逐語で残す**。各レンズが互いの案に乗っかる会話形式で、発言を発言順に全部記録する
  （触発の連鎖と「なぜそう思ったか」を省かない）。ラウンド数は固定せず、アイデアが出尽くすまで続ける。
- **議論は逐語で全ラリーを残す**（議事録）。要約で済ませない。ラウンド数を固定せず、噛み合う限り続け、
  推進派⇄懐疑派の往復を発言した順に全部記録する。ジャッジはこの議事録を読んでから裁定する。
- 事実に基づく議論にする。フィードURLの生死・HTTPコード・候補件数など、検証できる事実は
  実際に `npm run fetch` 等で確かめてから論拠にする（憶測で殴り合わない）。
- このログ自体はコミット対象（main に直接）。PR には参照として本文に要約＋リンクを載せる
  （議事録の全文はこのファイルに残り、PRからはリンクで辿れる）。
